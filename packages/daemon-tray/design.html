D · 设计规则

  • 定位只做三件事：daemon 生命周期、连接的主机、连接密码。不配置 agent、不开 workspace —— 那是主 app 的事。
  • 状态色绿 / 灰 / 红 / 旋转弧四种，含义全局一致；菜单、面板、托盘图标三处共用同一信号，禁止别处出现第四种状态色。
  • 操作可见性与状态互斥：运行中 → 重启/停止；停止 → 启动；执行中 → 按钮全部禁用 + 进度行，防止重复点击。
  • 破坏性「停止」「重启」不弹确认 —— 目标受众是开发者，daemon 停止不丢数据，误触代价是重启一次。主机「移除」弹确认（删除注册信息，对端需重新配对）。
  • 主机数据源paseo host ls --json（HostSummary），操作走 host enable/disable/rm/update/add。行内只显示：标签 + serverId + 状态；详情页展示 targetDescription、来源、lastOnlineAt、error。不显示、不可导出凭据。
  • 主机状态点五态直接映射 HostSummary.status：online=绿 · connecting=旋转弧 · offline=灰 · error=红（行内附错误码）· disabled=灰（附「已禁用」）。副行文字优先展示 error.message / nextRetryAt，让状态自解释。
  • 添加主机粘贴对端连接串即可，不做多步向导 —— 深度配对流程属于主 app，托盘只收连接串。
  • 密码数据源daemon status 的 authRequired 字段判断是否已设置；修改走 daemon set-password（哈希写 config.json，不回显明文），必须重启 daemon 才生效 —— 界面上把这一后果写在按钮旁，不藏在文档里。
  • Home默认管 ~/.paseo；启动环境变量 PASEO_TRAY_HOME 可指向其他 home（如开发目录），面板 Home 行如实显示。一期不做多 home 切换。
  • 开机自启不做。一期手动；需要时二期加「登录时启动」开关（LaunchAgent）。
